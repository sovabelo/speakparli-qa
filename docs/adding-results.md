# Adding results

1. Add a real finding using the [bug template](../bug-reports/TEMPLATE.md), or record a manual scenario with its data, steps, expected/actual result, date, build and verdict.
2. Keep sanitized screenshots and reports in a named folder under `evidence/`. Preserve before/after captures; add dated retests rather than overwriting earlier outcomes.
3. Link the new material from the appropriate evidence/bug index. Update [the summary](test-summary.md) only when a result was actually recorded. Keep browser observations and server checks separate.
4. Mark future work Not Run, missing prerequisites Blocked, and uncertain observations Needs Verification or INCONCLUSIVE. A developer fix or a screenshot filename is not a passed retest.
5. Remove secrets/identifiers from publication copies, check relative links, update the published-file SHA-256 manifest and mirror summary/status changes in Russian.
