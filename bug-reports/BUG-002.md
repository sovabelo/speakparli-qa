# BUG-002 — Sign-in error remains after a hard refresh
Environment: isolated local_qa, Russian UI. Evidence reviewed 2026-11-03; original testing 2026-11-02. Exact per-image application build and browser version were not recorded. Source diagnostic baseline is a working copy, not an immutable release.

Severity: Major (proposed). Priority: P1 (proposed). These are portfolio assessments, not external tracker decisions.

Status: **Partially verified — browser retest pending**.

Preconditions: Submit incorrect synthetic credentials in local QA.

Steps to reproduce:
1. Open sign-in in local QA and submit incorrect synthetic credentials with otherwise valid form fields.
2. Hard-refresh the sign-in page and observe the failure message; request counters require separate diagnostics.

Expected result: Refresh should not unintentionally replay credential submission or consume new attempts.

Actual result: Failure message persists in the before screenshot. The image alone does not prove the HTTP method or a counter increment.

Historical tester decision: the issue was closed after the limited GET diagnostic. That decision does not establish a complete fix.

Retest result: The read-only diagnostic proves unchanged counter/expiry across five GETs. Full browser POST replay remains INCONCLUSIVE. The after image still displays a restriction.
